# TruthLens AI

A fake-news classifier web app: your existing **scikit-learn TF-IDF + Logistic Regression** pipeline, served by **FastAPI**, with a **Next.js** light-editorial frontend (ivory / sage palette, DM Serif Display + Inter).

> **Read this first.** The bundled model was trained on a *synthetic, template-generated* 400-row dataset. Its 100 % test scores show the pipeline works end to end; they say nothing about real-world accuracy. Predictions are statistical pattern matches on wording, **not fact-checks**.

## Architecture

```
Browser --> Vercel (Next.js frontend) --HTTPS--> Render (FastAPI + saved Pipeline)
```

```
truthlens-ai/
|- frontend/            Next.js 15 (App Router), TypeScript, Tailwind 3, Recharts, Framer Motion
|  |- src/app/          /  /analyze  /analytics  /batch  /about
|  |- src/components/   Nav, Footer, ConfusionMatrix, ResultsTable, ModelSnapshot, ui/*
|  |- src/lib/          api.ts (typed client), csv.ts (export + table logic)
|  `- test/             Vitest: API client, CSV/table logic, analyzer workflow
|- backend/
|  |- src/              YOUR original ML package, unchanged (config, preprocess, data_loader, train, predict, utils)
|  |- api/              FastAPI: main.py, schemas.py, settings.py, ratelimit.py, services/model_service.py
|  |- app/streamlit_app.py   original Streamlit UI (kept)
|  |- models/           fake_news_model.pkl, metrics.json, confusion_matrix.png, evaluation.json
|  |- data/sample_data.csv
|  |- scripts/generate_evaluation.py
|  `- tests/            test_preprocess.py (yours) + test_api.py
|- render.yaml          Render blueprint for the API
`- .env.example
```

Model artifacts live inside `backend/` (rather than a top-level `model/`) so the API deploys from that single directory and your `src/config.py` paths work untouched.

**Reused vs. added.** `FakeNewsPredictor` is used as-is for single predictions and explanations. Batch uses the same `clean_text` and the same pipeline with one vectorised `predict_proba` call. As in training, headline and body are joined before cleaning. `models/evaluation.json` was generated by reproducing your train/test split (seed 42, stratified) and applying the *saved* model; it gives exactly `[[40, 0], [0, 40]]`, matching your PNG. Nothing was retrained.

## Run locally

```bash
# API (http://localhost:8000, docs at /docs)
cd backend
python -m venv venv && source venv/bin/activate      # Windows: venv\Scripts\activate
pip install -r requirements-dev.txt
uvicorn api.main:app --reload --port 8000

# Frontend (http://localhost:3000)
cd frontend
cp .env.example .env.local                            # NEXT_PUBLIC_API_URL=http://localhost:8000
npm ci && npm run dev
```

## Tests

## API

| Route | Purpose |
|---|---|
| `GET /health` | liveness + whether the model loaded |
| `GET /api/model-info` | architecture, hyper-parameters, evaluation, limits |
| `POST /api/predict` | `{"title"?: str, "text": str}` returns label, confidence, probabilities, top_features |
| `POST /api/predict/batch` | multipart `file` (.csv with `text`, optional `title`) returns per-row results + summary |

```bash
curl -X POST $API/api/predict -H 'Content-Type: application/json' \
  -d '{"title":"Optional headline","text":"SHOCKING: they do not want you to know!!!"}'
curl -X POST $API/api/predict/batch -F "file=@backend/data/sample_data.csv"
```

Batch rows are `status: "ok"` (predicted) or `"skipped"` (empty text, over-length, or nothing left after cleaning) with a `reason`. Skipped rows are never classified. The UI export keeps your original columns, adds prediction columns, and prefixes cells starting with `= + - @` with `'` to block spreadsheet formula injection.

### Environment variables

| Variable | Where | Default | Notes |
|---|---|---|---|
| `NEXT_PUBLIC_API_URL` | frontend | `http://localhost:8000` in dev only | **Required in production**; a production build refuses to call localhost |
| `CORS_ORIGINS` | backend | `http://localhost:3000` | comma-separated exact origins, e.g. your Vercel URL |
| `CORS_ORIGIN_REGEX` | backend | none | optional, for Vercel preview URLs |
| `MAX_UPLOAD_BYTES` / `MAX_BATCH_ROWS` / `MAX_TEXT_CHARS` | backend | 2 MB / 1000 / 20000 | |
| `RATE_LIMIT_PER_MIN` | backend | 60 | per-IP, in-memory (batch costs 5); `0` disables |
| `TRUST_PROXY` | backend | 0 | set `1` on Render so the limiter sees client IPs |
| `MODEL_PATH` | backend | `models/fake_news_model.pkl` | |

## Deployment

### Why Render for the API (not Vercel Functions)
The ML dependencies (scikit-learn, SciPy, NumPy, pandas) take roughly **330 MB installed** in the environment this was built in (sklearn 47, scipy 111 + 30 libs, numpy 42 + 28 libs, pandas 73 MB), before FastAPI. That is at or above bundle sizes serverless Python runtimes have historically allowed, and a pickled model adds cold-start cost. I did **not** test a Vercel Functions deployment, so check Vercel's current Python limits if you want to try. A long-running Render service sidesteps the question, so `render.yaml` targets it. Deploying the frontend to Vercel does **not** deploy the API.

### 1. API on Render (do this first)
1. Push this repo to GitHub.
2. Render: **New > Blueprint**, select the repo (uses `render.yaml`; root dir `backend`, start command `uvicorn api.main:app --host 0.0.0.0 --port $PORT`, health check `/health`).
3. Set `CORS_ORIGINS` to your Vercel URL once you have it (no trailing slash).
4. Verify: `curl https://<service>.onrender.com/health` should return `{"status":"ok","model_loaded":true}`. The free plan sleeps when idle, so the first request can take 30-60 s; the UI shows a timeout message and lets you retry.

### 2. Frontend on Vercel
1. Vercel: **Add New > Project**, import the GitHub repo.
2. **Root Directory: `frontend`** (auto-detected as Next.js).
3. Environment variable: `NEXT_PUBLIC_API_URL = https://<service>.onrender.com` (Production and Preview).
4. Deploy, then set `CORS_ORIGINS` on Render to the Vercel URL (add `CORS_ORIGIN_REGEX` if you want preview deployments to work).
5. Redeploy by pushing to the connected branch. Changing `NEXT_PUBLIC_API_URL` needs a redeploy because it is baked in at build time.

## Security notes
Pydantic validation; size, row and length limits; UTF-8-only CSV parsing (everything read as text); files handled in memory and never written to disk; submitted text is not stored or logged; validation errors do not echo input; generic 500s with no stack traces or paths; exact-origin CORS; per-IP rate limiting; the API loads the model only from its configured path and has no retraining endpoint. This is sensible hardening for a demo, not a claim of production-grade security. The rate limiter is per process; use an edge limiter if you scale out.

## Known limitations
No real-browser or responsive-viewport testing was possible when this was built, so check the layout at 375 / 768 / 1280 px yourself. No résumé link or personal details were supplied, so none appear. To measure real accuracy, retrain on a real labeled dataset (`data/sample_data.csv`, columns `title,text,label`): run `python -m src.train`, then `python scripts/generate_evaluation.py`.
